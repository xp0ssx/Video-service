MetadataForm с сохранением черновиков, серверные права и атомарная перестановка.
Роуты и бизнес-правила сохраняются.

## Дизайн-система и технические решения

Фон light #fff / dark #0f0f0f; поверхность #f2f2f2 / #272727;
текст #0f0f0f / #f1f1f1; вторичный #606060 / #aaa; border #d9d9d9 / #3f3f3f.
Акцент интерфейса — синий focus/link; красный используется на timeline плеера.
Системный sans-serif, базовый текст 14 px, карточки 16 px/600, watch title 20 px/700.
Spacing 4/8/12/16/24/32; radius 8/12 и pill; кнопки 36–40 px, icon targets 40 px.
Нативные range/select сохраняют клавиатурную семантику; focus-visible общий.

Плеер: собственная небольшая React-оболочка над существующим HTMLVideoElement.
Сохраняет прямой same-origin src `/api/videos/:id/media`, браузерный streaming и Range;
не требует SDK, blob/fetch полного файла, HLS или изменения backend.
Альтернатива — React player library; для единственного MP4 не даёт необходимой
дополнительной transport-функции и увеличивает зависимости. Цена решения — собственные
регрессии доступности, синхронизации media events и controls.

План: общие компоненты → темы/shell → лента/поиск → player/watch/comments →
каналы/плейлисты/формы → сборка контейнера → E2E и визуальная корректировка.

### Что оставалось после обрывов

Не было итогового протокола. Из переданного контекста завершение последних
`channels_playlists.cjs`, `scripts/run_checks.py` и дополнительных frontend-проверок

по сохранённым артефактам нельзя; их результаты здесь не засчитываются.
Каналы/плейлисты и целевые frontend-сценарии заново проверены ниже.

Обнаружено расхождение окружения: работающий web обслуживал старые
`index-D2HyDNhM.css` / `index-DquDbNfz.js`, тогда как текущие исходники собираются
в `index-BkMvc623.css` / `index-hgFEOnOO.js`. Перед E2E пересобран образ и обновлён
только web через `docker compose up -d --no-deps --no-build web`. Backend,
volumes и пользовательские данные не удалялись. Созданы только синтетические
тестовые аккаунты, ролики и плейлисты, необходимые существующим E2E.

`docker compose build web` завершился ошибкой окружения: отсутствует плагин
`docker-buildx`. Успешная альтернатива без изменения установщика и настроек:
`DOCKER_BUILDKIT=0 docker build --target runtime -t video-service-frontend:0.1.0 frontend`.
Оба результата сохранены в логах. Это исправление локального состояния сборки,
а не изменение кода приложения.
